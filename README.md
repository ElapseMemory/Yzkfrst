# Safe Page Translator

全新仓库用于开发一个面向 Chromium 浏览器的安全网页翻译扩展。我们已经清理了旧文件，并准备了一个符合 Manifest V3 规范的扩展骨架，方便继续迭代功能。

## 当前结构

```
extension/
├── manifest.json         # 扩展配置（Manifest V3）
├── popup.html/.js/.css   # 弹窗 UI 与交互逻辑
├── options.html/.js/.css # 设置页，用于配置翻译接口
└── scripts/
    ├── background.js     # Service Worker，负责上下文菜单、模板渲染与接口请求
    └── content-script.js # 内容脚本，整页翻译、语言检测、划词气泡与悬浮窗交互
```

## 主要特性

- **可配置的翻译服务**：在设置页填写任意 HTTPS 端点、HTTP 方法以及 API Key（只保存在本地同步存储）。
- **LLM 友好的 Prompt 模板**：使用 Mustache 风格占位符自定义提示词内容，例如 `{{text}}`、`{{sourceLanguage}}` 等。
- **可定制请求体与请求头**：通过 JSON 模板生成 LLM 或传统翻译接口所需的消息格式，支持自定义 Authorization、模型等字段。
- **响应路径解析**：设置点号语法路径（如 `choices.0.message.content`）即可从复杂的 LLM 返回值中提取最终译文。
- **整页翻译面板**：内容脚本批量采集可见文本节点，分块调用自定义接口完成整页翻译，并保留前后空白与原文缓存，避免重复翻译。
- **语言检测模式**：支持手动指定源语言、基于字符统计的快速检测以及调用同一接口（或独立端点）的 LLM 识别模式。
- **浮动悬浮窗**：当检测到页面语言与目标语言不一致时自动弹出悬浮窗，提供“整页翻译”按钮，并预留后续扩展按钮位。
- **划词气泡与弹窗入口**：支持上下文菜单触发划词翻译，也可以在弹窗输入文本或一键唤起当前标签页的整页翻译。

## 语言识别模式

在设置页的“语言识别与整页翻译”分组中可以选择：

- **手动**：始终使用默认源语言，跳过自动检测。
- **自动检测（字符统计）**：根据字符脚本频率判断常见语种（中/英/日/韩/俄/阿/印地等）。
- **调用接口识别语言**：使用自定义 Prompt、请求体和响应路径模板，将识别任务交给配置的 API 或 LLM 服务。

识别结果会在浮窗中展示，并用于决定是否自动提示整页翻译。若页面文本极少，悬浮窗会提示“网页可能主要由图片或自定义组件构成”。

## 整页翻译工作流

1. 安装扩展并在设置页配置翻译端点、API Key、Prompt 模板等信息；需要时可同时配置语言识别模板。
2. 打开任意网页，扩展会在后台收集文本样本并尝试识别语言。若检测到目标语言不同，会在右下角展示悬浮窗。
3. 点击悬浮窗或弹窗中的“翻译整页”按钮，内容脚本会按照设定的批量大小（默认 8 个文本块）依次调用接口。翻译状态会实时更新，完成后可继续在同一页面上操作。
4. 划词翻译或上下文菜单仍旧可用，适合针对性检查译文。

## 下一步建议

- 选择或自建一个翻译 API，并在 `options` 页面里配置翻译与语言识别的端点、Prompt 模板和响应路径。
- 如果需要额外的上下文或后处理，可在 `background.js` 中调整模板渲染逻辑或批量处理策略。
- 根据需求扩展 UI，例如历史记录、本地缓存或在悬浮窗中新增快捷按钮。
- 对于以图片或 Canvas 呈现文字的网页，可结合 OCR/截图方式获取原文，再通过扩展发送给自定义接口处理。

## 开发与调试

1. 在浏览器中打开 `chrome://extensions`。
2. 打开右上角的“开发者模式”。
3. 点击“加载已解压的扩展程序”，选择本仓库下的 `extension` 目录。
4. 修改代码后，可以在扩展管理页中点击“更新”快速刷新。
